# 公网访问是怎么实现的

[返回 README](../README.md) · [Slurm 运行步骤](deploy_slurm.md) · [普通机器运行步骤](deploy_local.md)

## 先分清三个角色

可以把 Demo 想成一间需要接待访客的工作室：GPU 机器负责处理音频，Gradio 页面负责让访客提交音频和查看文字，而公网入口负责让外面的访客找到这间工作室。

| 角色 | 实际做什么 |
| --- | --- |
| 自己的 GPU 机器 / Slurm 计算节点 | 保存权重、运行模型、生成识别和翻译结果 |
| Gradio 应用 | 提供网页、接收音频、调用模型 |
| Gradio 公网分享服务器 | 提供可从外部访问的 HTTPS 地址，把请求转交给自己的应用 |

使用 `--share` 并不是把模型上传到 Gradio 服务器。模型和应用仍在自己的机器上，分享服务器只是转发入口。[Gradio 官方分享说明](https://gradio.app/guides/sharing-your-app)

## 情况一：GPU 机器可以连接互联网

运行 `scripts/run/serve_share.sh`，或提交 `scripts/slurm/serve_direct.sh` 时，程序先检查公网连接，再加载模型和启动网页，最后由分享客户端向 Gradio 建立一条持续连接并取得 HTTPS URL。

```text
浏览器 → Gradio 公网分享服务器 → GPU 机器上的 Gradio → GPU 模型
浏览器 ← Gradio 公网分享服务器 ← GPU 机器上的 Gradio ← 文本结果
```

GPU 机器主动连接外部分享服务器，因此不要求外面的浏览器直接连到机器的 7860 端口。只要连接保持、应用仍在运行，浏览器就能通过 `PUBLIC_URL` 使用它。

## 情况二：计算节点不能联网，登录节点可以

很多集群允许登录节点联网，却限制计算节点连接公网。这时需要一个“能对外接待、能对内送信”的登录节点。

整个启动过程按以下顺序进行：

1. 在登录节点准备 Python 环境、模型目录和本地配置，再提交 GPU 作业。
2. Slurm 分配计算节点；作业从这个计算节点通过 SSH 连接登录节点。
3. 作业先检查这个 SSH 会话中的登录节点能否连接 Gradio，能否建立分享连接；失败时直接结束，不加载模型。
4. 检查通过后，作业启动计算节点上的模型与网页。SSH 同时建立内网转发通道。
5. 登录节点等待计算节点网页就绪，再向 Gradio 分享服务器建立持续连接，打印真正的 `PUBLIC_URL`。
6. 在其他电脑或手机打开这个 HTTPS 地址，上传音频或录音。请求经登录节点转发到计算节点，文本结果沿原路返回。

```text
你在其他设备上的浏览器
        ↓ 点击 HTTPS 分享地址，上传音频
Gradio 公网分享服务器
        ↓ 通过登录节点主动建立的持续连接
集群登录节点：接待公网请求
        ↓ 通过 SSH 转发通道
集群计算节点：接收音频 → GPU 推理 → 返回文字
```

这里的“SSH 转发”可以理解为：访问登录节点上的一个本地端口，会被送到计算节点上的网页服务。项目默认把登录节点的 `17860` 接到计算节点的 `7860`；浏览器无需知道这两个端口，只需要打开公网 URL。

因此，计算节点不必连接 Gradio 公网服务器；它只需要能够 SSH 到登录节点。登录节点需要能够联网、运行分享客户端，并能读取项目及 Python 环境。集群也需要允许这种转发。任一条件不满足，脚本本身无法创造网络出口。

## 情况三：使用自己的固定域名

Gradio 分享 URL 是临时地址。如果希望一直使用自己的域名，可以使用一台公网服务器负责 HTTPS 入口：

```text
浏览器 → 自己的 HTTPS 域名 → 公网服务器上的 Caddy
                                      ↓ SSH 转发
                              GPU 机器上的 Gradio 和模型
```

Caddy 是把域名访问转交给后端应用的 Web 服务，并负责 HTTPS 证书。公网服务器可以没有 GPU；只要 GPU 机器能 SSH 到它，就能建立通道。若 GPU 机器本身已有公网入口，Caddy 和 Gradio 直接部署在同一台机器即可，不再需要 SSH 转发。

## 哪个地址应该在浏览器打开？

| 日志/配置中的地址 | 含义 | 能否在别的设备直接使用 |
| --- | --- | --- |
| `127.0.0.1:7860` | 只在运行程序的机器上可见 | 不能 |
| `0.0.0.0:7860` | 表示监听机器的网络接口 | 这不是浏览器目标地址 |
| 局域网 IP 加端口 | 同一局域网内可访问，仍需防火墙允许 | 通常不能从公网使用 |
| `PUBLIC_URL=https://….gradio.live` | 实际 Demo 的 Gradio 公网入口 | 可以，前提是服务仍在运行 |
| 自己配置的 HTTPS 域名 | 固定公网入口 | 可以，前提是代理、后端与通道均正常 |

`--check-only --test-tunnel` 创建的是诊断连接，检查结束就关闭；不要用检查过程中出现的地址访问 Demo。等正式作业打印 `PUBLIC_URL` 后再打开。
